    Bulk differential expression¶

    Intro¶

    edge_rs is edgeR's quasi-likelihood pipeline and limma-voom for Python, without R. The numerics are a Rust port of both packages, checked against edgeR 4.8.2 and limma 3.66.0. The Python layer is thin on purpose: counts go in as a NumPy array, results come out as polars frames, and every function is named after the R function it reproduces. If you have run glmQLFit() or voom() before, there is nothing new to learn here.

    The flow is the one from the edgeR and limma user guides:

    filter_by_expr()       # drop genes too low to test
calc_norm_factors()    # TMM
  -> glm_ql_fit()   -> glm_ql_ftest()  -> top_tags()    # edgeR QL
  -> voom_lm_fit()  -> ebayes()        -> top_table()   # limma-voom

    Two conventions to keep in mind throughout. Counts are genes x samples, as in R. And a design can be a plain NumPy matrix or a polars frame; with the frame, its column names become coefficient names you can test by name.

    Filtering¶

    filter_by_expr() is edgeR's filterByExpr(): keep a gene if it reaches a minimum count-per-million in enough samples to make up the smallest group. Pass the grouping (any sequence of labels, a NumPy array or a polars Series) or a design.

    Normalisation¶

    TMM normalisation factors next, on the kept genes. The one subtlety is the library size. edgeR's keep.lib.sizes = TRUE default keeps the library sizes of the full count matrix after filtering, so we pass the unfiltered column sums explicitly. Leave lib_size out and you get the column sums of whatever you hand in, which after a filter is not the same thing.

    With a DgeList¶

    If carrying lib_size around by hand sounds like a bug waiting to happen, make_dgelist() bundles counts, library sizes, normalisation factors and annotation into a frozen record, edgeR's DGEList minus the S4. Subsetting genes keeps the library sizes of the full matrix, and every function that takes counts takes a DgeList instead and reads both from it.

    edgeR quasi-likelihood¶

    glm_ql_fit() fits the negative binomial GLM per gene and squeezes the quasi-likelihood dispersions towards a trend, as edgeR 4's glmQLFit() does.     limma-voom¶

    Same data, same design, limma's route. voom_lm_fit() is edgeR's voomLmFit(): voom's precision weights and the weighted linear model in one step, with structural zeros (a group that is all zero for a gene) handled properly. Then contrasts_fit() and ebayes(), as in limma.

    What is not there (yet)¶

    The Rust crate has more than the bindings expose so far. Not in Python yet: the exact test, glmFit() / glmLRT() / glmTreat(), diffSpliceDGE(), limma's moderated F-test across several coefficients (topTableF()), duplicateCorrelation() and sample weights. NEBULA lives in bixverse, where the single cell data is.
