    edge-rs¶

    edgeR's quasi-likelihood pipeline and limma-voom for Python, with the numerics in the edge-rs Rust crate. No R, no rpy2. NumPy in, polars out, and every function named after the R function it reproduces.

    Install¶

    uv pip install edge-rs

    The runtime dependencies are NumPy, polars and beartype. That's it.

    Thirty seconds¶

    import edge_rs

# counts: (n_genes, n_samples), as in edgeR
res = edge_rs.run_edger_ql(counts, design, feature_ids=genes, coef="treated")
res = edge_rs.run_limma_voom(counts, design, feature_ids=genes, coef="treated")

    Or step by step, as in edgeR and limma:

    keep = edge_rs.filter_by_expr(counts, design=design)
lib_size = counts.sum(axis=0)
nf = edge_rs.calc_norm_factors(counts[keep], lib_size=lib_size)

fit = edge_rs.glm_ql_fit(counts[keep], design, lib_size=lib_size, norm_factors=nf)
edge_rs.top_tags(edge_rs.glm_ql_ftest(fit, coef="treated"))

vfit = edge_rs.voom_lm_fit(counts[keep], design, lib_size=lib_size, norm_factors=nf)
edge_rs.top_table(edge_rs.ebayes(vfit), coef="treated")

    If you would rather not carry lib_size around, make_dgelist bundles counts, library sizes, normalisation factors and annotation. Subsetting it keeps the library sizes of the full matrix, as edgeR's keep.lib.sizes = TRUE does, and every function above takes it in place of the counts:

    dge = edge_rs.make_dgelist(counts, genes=pl.DataFrame({"gene_id": genes}))
dge = edge_rs.calc_norm_factors(dge[edge_rs.filter_by_expr(dge, design=design)])
fit = edge_rs.glm_ql_fit(dge, design)
edge_rs.top_tags(
    edge_rs.glm_ql_ftest(fit, coef="treated"), feature_ids=dge.genes["gene_id"]
)

    Conventions¶

    • Counts are genes x samples. Single cell tools are the other way round; hand over x.T. Non-contiguous arrays are fine.
    • A design is a NumPy matrix or a polars frame. With a frame, the column names become coefficient names and coef="treated" works.
    • Everything is 0-based. Coefficients by position, feature_id when you pass no ids.
    • Results are polars frames with snake_case columns (log_fc, p_value, fdr, adj_p_value). top_tags and top_table sort as R does; the pipelines keep the input order.

    How close to R?¶

    The Rust crate is checked against edgeR 4.8.2 and limma 3.66.0 on committed fixtures, and the Python test suite runs the same fixtures through the bindings. Filtering, TMM, CPM, the QL F-test, voom, eBayes(), contrasts.fit() and topTable() all match to the tolerances in the crate's end-to-end tests.

    What's in it¶

    Python R
    make_dgelist, DgeList edgeR::DGEList
    filter_by_expr edgeR::filterByExpr
    calc_norm_factors edgeR::calcNormFactors
    cpm, ave_log_cpm edgeR::cpm, edgeR::aveLogCPM
    remove_batch_effect limma::removeBatchEffect
    glm_ql_fit, glm_ql_ftest, top_tags edgeR::glmQLFit, edgeR::glmQLFTest, edgeR::topTags
    voom, voom_lm_fit, lm_fit limma::voom, edgeR::voomLmFit, limma::lmFit
    make_contrasts, contrasts_fit limma::makeContrasts, limma::contrasts.fit
    ebayes, top_table limma::eBayes, limma::topTable
    run_edger_ql, run_limma_voom the above, chained

    For single cell data, bixverse does the pseudobulking (and NEBULA); see the pseudobulk vignette.
